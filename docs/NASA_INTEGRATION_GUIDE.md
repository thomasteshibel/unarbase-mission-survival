# NASA Open Data Integration Guide

This guide establishes the engineering protocols and scientific integrity standards for integrating official NASA open datasets into the LunarBase Junior Astronaut Mission Trainer.

---

## 1. Core Integration Rules

1. **Strict Multi-Tier Classification**: Every dataset must be assigned one of the established non-overlapping categories:
   - `REAL_NASA_DATA`: Physical observations and telemetry from NASA spacecraft, detectors, or ground stations.
   - `RESEARCH_EVIDENCE`: Published peer-reviewed research and bio-experimental metadata archived in NASA repositories.
   - `LITERATURE_BENCHMARK`: Published peer-reviewed scientific literature summaries, flight data compendia, and external international missions used for comparative education.
   - `SIMULATED_DATA`: Educational model values generated by the mission simulation engine.
2. **Provenance Mandate**: An external dataset cannot be displayed or adapted without complete provenance metadata:
   - Dataset name
   - Official source agency/node
   - Valid HTTPS source URL
   - Retrieval timestamp
   - Measurement or observation period
   - Spatial applicability
   - Temporal applicability
   - Physical measurement units
   - Scientific description
   - Known limitations
3. **No Fabricated Telemetry**: Never fabricate API responses, measurements, units, or citations. If an external API is unreachable or rate-limited, display clear diagnostic feedback and gracefully render verified offline historical records.
4. **Physical Shielding Boundaries**:
   - Never equate heliospheric space weather (solar flares, CMEs) to in-habitat radiation doses without validated nuclear particle transport simulations; habitat regolith berming and storm shelter concepts are educational engineering models.
   - Never convert orbital or extraterrestrial dosimetry (ISS, MSL RAD) to crew exposure without transport code validation.
5. **No Medical Extrapolation**: Never treat space biology research metadata (e.g. rodent muscle loss) as real-time diagnostic predictions for fictional crew members.

## 2. API Integration Standards

### A. NASA DONKI (Space Weather)
- **Endpoint**: `https://api.nasa.gov/DONKI/` (`FLR`, `CME`, `SEP`, `GST`)
- **Key Strategy**:
  - Default: `DEMO_KEY` (public, subject to rate limits).
  - Custom Key: User can input their personal `api.nasa.gov` key in Settings.
  - Security Notice: Browser-side keys are stored in `localStorage` and visible in web developer tools. Users are warned never to supply sensitive production keys.
- **Offline Fallback**: Curated baseline from the May 2024 Solar Superstorm (AR 13664 X8.7 flare, full halo CME, S3 SEP proton event, G5 geomagnetic storm).

### B. NASA OSDR & LSDA (Space Biology & Experiments)
- **Endpoint**: `https://osdr.nasa.gov/osdr/data/search`
- **Data Shape**: Query search results containing study accessions (`OSD-xxx`), experiment identifiers (`OS-xxx`), titles, organisms, and experimental payloads.
- **Offline Fallback**: Curated flight records independently verified against official NASA repository metadata:
  - `OSD-379` (Study Accession): *Transcriptional profiling of livers from mice flown on Rodent Research Reference Mission-1 (RRRM-1)* (*Mus musculus*, liver).
  - `OS-452` (Experiment Identifier): *Effect of Weightlessness on Tissue Regeneration in Rodents* (*Rattus norvegicus*, cutaneous/connective tissue repair).
  - `OSD-665` (Study Accession): *Transcriptional profiling of right extensor digitorum longus muscle from mice flown on the RR-23 mission.* (*Mus musculus*, right EDL skeletal muscle).
  - `OSD-566` (Study Accession): *Sexual Dimorphism during Integrative Endocrine and Immune Responses to Ionizing Radiation in Mice -- Adrenal data* (*Mus musculus*, adrenal gland). **Direct study record currently reported unavailable on NASA OSDR portal; payload parameters preserved from NASA archives.**
  - `OSD-120` (Study Accession): *Genetic dissection of the Arabidopsis spaceflight transcriptome: Are some responses dispensable for the physiological adaptation of plants to spaceflight?* (*Arabidopsis thaliana*, whole seedling).

### C. NASA RadLab (Radiation Dosimetry)
- **Official Endpoint**: `https://visualization.osdr.nasa.gov/radlab/api/`
- **Query Syntax**:
  - Requires `format=json` query parameter (e.g. `https://visualization.osdr.nasa.gov/radlab/api/?format=json`).
  - Supports filtering parameters: `spacecraft`, `instrument`, `query`.
- **Documented Native Rate Units**:
  - Absorbed dose rate: $\mu\text{Gy/hour}$
  - Dose equivalent rate: $\mu\text{Sv/hour}$
- **Integration Method for Displayed Reference Values**:
  - Native fields are preserved in hourly units ($\mu\text{Gy/h}$, $\mu\text{Sv/h}$).
  - Calculated 24-hour quiet reference baselines ($\text{rate} \times 24\text{h}$) are transparently documented as nominal extrapolated baselines, not observed daily cumulative totals.
- **Offline Fallback**: Verified flight telemetry from ISS Columbus Liulin-6R, ISS Service Module TEPC, MSL RAD (Cruise & Gale Crater, Zeitlin et al. 2013 / Hassler et al. 2014), and Lunar Surface LND (CNSA / Kiel University, Wimmer-Schweingruber et al. 2020).

## 3. Step-by-Step Procedure for Ingesting New Datasets

1. **Verify Source Authority**: Confirm the dataset originates from an official NASA archive (e.g., PDS, OSDR, DONKI, SVS, or api.nasa.gov).
2. **Document Provenance**: Construct a validated provenance object using `createProvenanceRecord()` in `src/data/provenance.js`.
3. **Validate Units**: Ensure all units match supported dimensions in `src/data/unitConverter.js` and normalize them via `src/data/dataNormalizer.js`.
4. **Implement Resilient Client**: Use `fetchJson()` from `src/data/api/apiClient.js` with timeout handling and error classification.
5. **Bundle Verified Fallback**: Create a curated, authentic offline fallback dataset in `src/data/curated/`.
6. **Automated Testing**: Write unit tests with mock responses in `tests/` verifying nominal retrieval, rate-limit rejection, network failure fallback, and schema compliance.
